# 第二阶段：核心运行包与可选资产边界

## 目标

按第一性原理把发布物拆成两个清晰边界：

1. 默认技能运行包只携带当前默认 `pure-images` 主链、核心 Pillow 依赖和默认 `core-v1.2` 角色资产。
2. 完整下载包继续保留打印、社媒、历史兼容脚本/依赖和阶段性资产，供需要这些分支时使用。
3. 任一发布物都不得携带用户项目目录 `projects/`。

## 不做的事

- 不重构 `generation_queue.py`、`project_preflight.py` 或图片生成链。
- 不删除仓库中的可选脚本、历史资产和完整依赖。
- 不改变项目 schema、默认输出格式或既有生产流程。

## 实施顺序

1. 先用测试固定默认包排除可选资产、完整包保留可选资产且排除项目产物。
2. 在打包器中增加明确的路径边界：`projects/` 为全包禁区；打印、社媒、历史兼容脚本/参考/依赖，以及阶段性角色包、STYLE-06 和打印字体只进入完整下载包。
3. 重新生成根目录 `MANIFEST.json`，确保它只描述默认运行包。
4. 运行聚焦测试和全量测试，检查归档内容、清单哈希和体积变化。
5. 更新发布说明，说明何时使用默认包、何时使用完整下载包。

## 验收标准

- 默认包不含 `core-v1.3`、`style-06-v0.1`、打印字体及其元数据。
- 默认包不含打印、社媒和历史兼容脚本，也不含完整依赖清单；核心包提供 `requirements-core.txt`。
- 完整下载包仍含上述可选资产及可选脚本。
- 完整下载包提供 `requirements.txt` 和 `requirements-optional.txt`。
- 两种包都不含任何 `projects/` 路径。
- 根 `MANIFEST.json` 与默认运行包内生成清单完全一致。
- 现有全量测试不回归。
