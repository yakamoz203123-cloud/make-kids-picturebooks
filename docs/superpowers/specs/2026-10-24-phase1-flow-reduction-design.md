# 第一阶段流程精简设计

## 意图

以第一性原理压缩 `make-kids-picturebooks` 的默认生产路径，减少重复读取、重复全书检查和可选分支对主流程的干扰，同时保持知识正确性、年龄适配、视觉连续性、隐私边界、可恢复性和历史项目兼容。

## 核心结果

默认流程只围绕五项结果组织：

1. 知识正确；
2. 年龄适配；
3. 故事可读；
4. 角色与画面连续；
5. 成品可验证、可交付。

## 目标

- 让 `SKILL.md` 负责入口、默认契约和分支路由，不重复承载完整生产手册。
- 让 `references/production-workflow.md` 成为默认生产流程的唯一详细来源。
- 区分整本门禁、页面轻量检查、队列状态和最终验收的责任。
- 新项目默认走“输入契约 → 知识门禁 → 故事/分镜 → 资产锁定 → 一次整本预检 → 串行逐页生产 → 局部返工 → 确定性交付”。
- 继续项目只读取项目摘要、当前页依赖、有效预检回执和队列状态。
- 将社媒、PDF、打印、迁移、性能诊断和完整兼容回归明确为按需/历史分支。

## 非目标

- 不改 `schema_version: 1`。
- 不删除旧脚本、旧版布局或历史迁移能力。
- 不合并教育目标、概念卡、故事、分镜等数据结构。
- 不改变 `pure-images` 默认输出、串行生图和人工视觉审核要求。
- 不接入新的图像 API，不提高图片模型并发。

## 单一职责边界

| 对象 | 唯一职责 |
|---|---|
| 项目契约 | 来源、年龄、输出模式、隐私和用户授权 |
| knowledge whitelist | 允许使用的事实 |
| 故事/分镜产物 | 教育目标、故事、视觉事件和页面任务 |
| asset registry | 角色、画风、参考图和版本 |
| page manifest | 当前页面的生产约束 |
| generation queue | 领取、提交、候选、失败和恢复状态 |
| delivery manifest | 源图、派生图、哈希和交付文件关系 |
| review/acceptance | 内容、视觉、阅读和发布结论 |

## 目标流程

```text
新项目：输入契约 → 知识门禁 → 故事/整本分镜 → 资产锁定
      → 一次 strict 预检 → 串行逐页生图 → 页面审核
      → 失败页局部返工 → pure-images 确定性交付 → 最终验收

续做项目：项目摘要 → 当前页任务/依赖 → 预检回执复用检查
      → 当前页轻量检查 → 串行生图 → 页面审核
```

## 重新运行整本流程的条件

研究内容、年龄档、故事、页数、关键角色/画风、连续性契约、输出模式或预检规则发生变化，或者无法证明关键输入未变时，必须重新运行整本 strict；单页提示词或单页资产变化只使当前页失效。

## 验证标准

- 新增契约测试能区分默认流程、续做流程和按需分支。
- 现有聚焦指导、发布门禁和打包测试继续通过。
- 主 Skill 不再把 PDF/打印/社媒作为默认生产步骤。
- 文档明确“技术成功不等于视觉批准”。
- 本地安装目录与隔离分支的 Skill 文档一致。
