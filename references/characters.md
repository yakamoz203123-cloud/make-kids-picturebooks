# 固定儿童伙伴与插画

首次设定三个完全虚构的儿童伙伴，先把名字、年龄、外形、服装、颜色和标准图标为 pending（待确认），向用户展示后暂停。只有用户确认后才标为 approved（已批准）并继续正式正文、逐页插画或整册制作。偏好可以不同，知识地位平等；每个人都能观察、动手、猜错与发现。不把具体性别或角色固定成聪明、胆小或犯错的人。

## 当前默认 core-v1.2 固定角色

本版已有批准的核心角色资产包，优先复用而不是重新设计：`assets/characters/core-v1.2/manifest.json`、`assets/characters/core-v1.2/manifest-receipt.json` 和 `assets/characters/core-v1.2/aliases.json`。公共别名固定为 `CHAR-GIRL-01`＝小熊（规范 ID `xiaoxiong`）、`CHAR-BOY-01`＝小猛（规范 ID `xiaomeng`）、`CHAR-MOTHER-01`＝妈妈（规范 ID `mother`）。服装、表情、动作、角度、双人互动和亲子互动必须从同一 v1.2 清单解析；别名、参考图、版本和回执不能被页面提示词覆盖。新角色只有在用户明确要求建立新版本并完成批准后才能加入，不得把页面临时描述当作角色定义。

## 故事阶段的角色身份锁定

正式故事编辑前，先从当前项目或系列清单建立一份轻量角色锁定：`canonical_name`（规范角色名）、`character_id`、公共别名、版本、approved/reused/temporary 状态、稳定外观和服饰策略。系列角色优先；正文、分镜、`visual_direction` 和页面提示词必须回写规范角色名。别名/同音字只能作为输入解析到同一 `character_id`，不能静默生成“小梦”等新写法；无法解析时暂停，不猜测。

如果确实选择新主角，必须明确记录“新角色必须”经过的创作选择，绑定角色档案、角色参考、年龄/外观和服饰策略后才能进入正式分镜。临时角色不能因为出现在一页正文或样图中自动成为系列角色。此规则只锁定身份连续性，不改动正式角色图片或既有资产。

页面生产使用 `assets/page-production-template.json` 和 `assets/page-production-registry.json`；每页记录公共别名、资产 ID、`style_master_id`、`page_delta` 与解析哈希。正式生成前使用与同一 Bible 版本对应的 `production_reference_path`，不要把整张角色设定总览页或原始儿童照片当作每页默认输入。

## 本机私有角色注册表

需要跨私有绘本复用时，可以在 `%USERPROFILE%/.codex/picturebook-private/characters/<id>-v<version>/` 保存角色档案。目录至少包含 `character-profile.json`、已批准的 `character-reference` 图和同版本的 `production-reference` 图；该目录不属于 Skill 仓库，不参与 Skill 打包。Skill 只读取档案中明确的批准状态、版本和路径，不扫描或上传原始照片。用户说出已批准角色名时，优先使用同一版本，并在项目页清单中写入项目内复制后的相对路径；跨年龄档或改设定必须建立新版本，不能覆盖旧版本。

用户可以明确授权把自己的孩子或其他真实儿童作为绘本角色原型，但这不等于授权公开照片或个人资料。此类角色必须建立在用户自己的私有项目中，原始照片、生成的角色参考图、姓名、学校、住址、联系方式和可识别标识都不得进入 Skill 仓库、GitHub 或未经授权的外部服务。不要把真实儿童照片直接当作公开插画素材；应先由用户确认经过风格化的角色设定图，并以该设定图作为正式参考。

私有角色 Bible 至少记录以下字段：`status`（`pending`、`approved` 或 `reused`）、`version`（版本号）、`canonical_reference_path`（标准参考图路径）、`privacy_scope: private` 和 `public_release`（默认 `not-approved`）。`approved` 只表示用户批准在私有绘本项目中使用该角色，不表示照片、角色图或角色资料可以公开发布。只有用户另行明确批准公开发布时，才可把 `public_release` 改为 `approved`；发布前仍需移除原始照片、个人信息、学校／品牌标识和可追溯元数据。

每页 `character_reference_path` 必须指向当前私有项目中同一份已批准、带版本号的 character Bible 参考图；不要把用户电脑路径硬编码进 Skill 文档。角色参考应放在私有项目目录（例如项目内的 `characters/v1/`），这样清单可以用项目相对路径校验，而公开 Skill 只保存规则和空模板。若角色年龄、发型、脸部特征或核心服装设定改变，保留旧版本并建立新版本，不默默覆盖；跨年龄档使用时重新确认，不把低龄真实照片自动推断成更大年龄的角色。

## 生产参考图与快速出图

展示型角色设定页和生产参考图是两种用途。前者用于用户确认角色，允许包含多表情、多姿势、服装变体和说明文字；后者用于正式图像生成，应是同一已批准 Bible 版本下的干净、低干扰参考，建议只保留正面或三分之四脸、一个全身视图和必要的侧面视图，不放标题、标签、英文单词、水印、拼贴边框或无关背景。生产参考图不替代 `character_reference_path`：每页仍记录 Bible 版本，同时在私有项目清单记录对应的 `production_reference_path`；两个路径必须属于同一角色版本，旧版本不能默默替换。

正式生成前先完成整册 `layout_design` 和目标 profile 预检，再使用一份稳定的 `production_reference_path`。默认一页只传一份生产参考图；只有当前动作确实缺少必要视角时才增加第二份。稳定基础提示词固定画风、角色不变特征、比例和禁项，每页只追加场景动作、道具数量、知识因果、连续性状态和文字安全区。这样既减少输入和等待，也降低展示页说明文字被图像生成器误当成画面内容的风险；图像仍不得生成文字，字幕由排版层加入。

提交或打包 Skill、模板和示例前，检查仓库差异与压缩包清单，确认没有儿童照片、角色参考图、私有 Bible、绝对本机路径或个人信息。若用户只批准了私有使用，任何对外发布、演示或共享都必须保持 `public_release: not-approved`，并用虚构或合成占位素材替代真实参考。

制作标准参考页：正面、侧面、身高比例、服装配色和常用表情。将这套已批准、版本化的参考页作为 character bible，保存稳定路径、批准状态与版本。项目已有 approved（已批准）角色时，可按明确版本号标为 reused（已复用）并跨书沿用，不重复索取确认；没有批准记录或无法确定版本时暂停询问。改设定时保留旧版并标记受影响册，不默默覆盖。`pending`（待确认）不等于 `approved`（已批准），样图中出现过也不会自动获得批准。

用户明确授权的临时测试角色只用于角色／画风试样，记录为 temporary（临时）并排除在正式系列角色、跨书复用清单和完成证据之外。临时角色不会因出现在样图或分镜中自动转为 approved（已批准）。

使用原创温暖手绘线条、柔和明亮色彩、丰富但不拥挤的生活场景。审美参考《波西和皮普》的阅读气质，不复制人物造型或具体构图。浅底、白边适合家用打印；不要为省墨删掉知识关键细节。

每页图像请求含：角色参考图、场景动作、构图、道具及数量、知识因果、与前页连续性、无文字要求。每页清单保存 `character_reference_path`，指向本页实际使用的 character bible 已批准版本；同一版本不得因文件名或工具默认值漂移。编辑前先查看目标图；有参考路径时依工具要求传入参考，缺少路径时按工具实际支持方式引用。不得假定参考图保证完全一致。

生成节奏采用“样页确认 → 串行逐页生成 → 相邻页复核 → 下一页”。旧版“两页一批”只作为历史兼容记录，不代表默认并行许可。每页一次生成，生成器已返回成功、任务仍在运行或结果目录可能已有文件时，先检查已有结果，不要重复提交相同请求；只有明确失败且没有输出时才做针对性处理，并记录失败原因。相邻页的角色、服装、道具和动作状态通过 `layout_review` 核对后再继续。

先完成整册分镜再生成图。插画与正文分别制作。检查实际像素和摆放尺寸：1024像素的图不能宣称在所有整页尺寸下均达300像素／英寸；可调整图像实际尺寸或按工具能力取得更清晰输出，不能伪造分辨率。

数量、桥梁连接、受力方向等需要精确时，使用程序绘制精确元素辅助呈现。程序图形不能替代故事所需儿童插画。逐页检查服装、身高、数量、动作与知识对象；失败页最多两轮针对性修订后仍有关键缺陷则保存阻碍。

图像工具缺失时保留分镜并明确仅文字完成。不要静默切换收费接口或要求用户在聊天粘贴密钥。
