# 小红书静态图文输出（明确请求时的可选成品）

用户明确选择可阅读图文成品时，才输出一套小红书静态图文；默认生产先交付无字源图和独立正文。它不是把横向打印页截图后上传：平台 profile 使用 `xiaohongshu-feed-3x4`，按3:4重新构图、生成源图并把文字合成进最终画面。图像层与文字层在生产中分开，最终逐页 PNG/JPEG 是一张已经融合图文的 `1080×1440` 成品；不会由本分支自动生成 PDF、家庭打印拼版、抖音/9:16或多套候选。旧版记录中的“当前唯一新输出”仅描述旧默认，不再适用于默认路径。

## Profile 选择

| profile | 用途 | 画布 | 源图比例 | 选择规则 |
| --- | --- | --- | --- | --- |
| `xiaohongshu-feed-3x4` | 小红书静态图文 | `1080×1440` | `3:4` | 明确请求时的可选输出 |

小红书页必须使用 `composition_mode: portrait-full-bleed` 与 `text_placement: in-scene`：插画背景连续覆盖竖版画面，文字位于画面内部的自然留白，不使用底部通栏或大块不透明文字卡。不能把横向图缩放、中心裁切或补大块空白冒充3:4；比例不符时必须重新构图并生成源图。可以沿用角色参考、主色和故事状态，但视觉焦点、主体安全区、文字安全区、平台界面避让区和图像提示词必须按小红书画布设计。

旧版本中可能存在 `social-vertical-9x16` 记录；底层校验器和渲染器为历史兼容仍可读取它，但新流程不得创建或交付该 profile。

新流程调用 `scripts/render_social_book.py`，不接受缺失或混用 profile 的整册版面；每页必须明确填写 `xiaohongshu-feed-3x4`。底层 `render_social.py` 的单页函数仍可省略 `profile` 参数，以便读取旧项目自身的 profile，但这不改变新整册入口的单一输出契约。

## 图像生成能力预检（必须）

在正式逐页插画前，先生成一张探针图：必须使用实际会调用的图像生成器，并针对目标 profile，再运行：

```bash
python3 "$SKILL_DIR/scripts/preflight_image_generation.py" /absolute/probe.png --profile xiaohongshu-feed-3x4
```

脚本读取探针的实际像素尺寸，而不是相信提示词、参数名或生成器的文字回执。当前新流程的小红书探针必须实际符合3:4（例如 `768×1024` 或 `1080×1440`）；通过后保存返回的 JSON 记录。如果返回 `image_generation_blocked`，必须停止正式插画、排版和完成声明。比如实际得到 `1280×720` 时，说明当前生成器只给了横图，不能缩放、中心裁切或补白后继续，必须更换支持原生比例的生成器或索取合格源图。旧项目若被用户明确要求复核9:16，才按旧项目自身 profile 单独预检；它不改变当前新流程的一套小红书输出契约。

## 快速生成与结果状态

先完成 `layout_design` 再调用图像生成器：提前锁定每页的 profile、主体安全区、文字安全区、视觉焦点和连续性状态，避免用昂贵的图像请求反复试排版。正式页使用私有项目中与 `character_reference_path` 同版本的 `production_reference_path`；展示型角色设定页不作为默认生产输入。稳定基础提示词固定画风、角色特征、目标比例和全局禁项，每页只加入短的场景增量，并明确图像不得生成文字。

通过探针和明确授权后，采用**每页一次生成、按页串行**。每页结束先检查已有结果、实际尺寸和比例，再决定是否提交授权范围内的下一页。若生成器已经返回成功、任务仍在运行或结果目录可能已有文件，先检查已有结果，**不要重复提交**相同请求；只有明确失败且没有输出时才记录失败原因，并遵守未知状态停止规则。相同页面的修订只修改场景增量，不重复发送整套角色说明和长篇故事。

## 生成前的契约

每页 `layout_design.social_layout` 至少记录 profile、画布、构图模式、文字放置方式、主体安全区、画面内文字安全区、避让区、源图比例和状态。默认小红书示例：

```json
{
  "profile": "xiaohongshu-feed-3x4",
  "canvas": {"width_px": 1080, "height_px": 1440},
  "composition_mode": "portrait-full-bleed",
  "text_placement": "in-scene",
  "subject_safe_area": [0.50, 0.20, 0.42, 0.54],
  "text_safe_area": [0.08, 0.12, 0.38, 0.24],
  "avoid_regions": ["top-ui", "bottom-ui"],
  "source_aspect_ratio": "3:4",
  "status": "pending"
}
```

旧项目如需在用户明确要求下保留抖音/长屏记录，可显式使用独立 profile；这不是当前新流程的默认输出：

```json
{
  "profile": "social-vertical-9x16",
  "canvas": {"width_px": 1080, "height_px": 1920},
  "subject_safe_area": [0.08, 0.10, 0.84, 0.62],
  "text_safe_area": [0.08, 0.76, 0.84, 0.14],
  "avoid_regions": ["top-ui", "bottom-ui"],
  "source_aspect_ratio": "9:16",
  "status": "pending"
}
```

坐标采用相对画布的 `[x, y, width, height]`，范围为 `0..1`。小红书的 `text_safe_area` 必须位于插画内部，不能使用贴近底缘的全宽文字栏；当前契约拒绝从 `y >= 0.72` 开始或 `y + height > 0.88` 的底部通栏。主体安全区应容纳人物脸、手、关键动作和知识证据；文字安全区应能放下本页字幕和对应的 `max_lines`。顶部和底部避让区是平台界面的通用保守区，不能把关键对象或字幕放进去。安全区只是设计约束，不是平台 UI 尺寸的永久保证；平台改版或投放场景变化时要重新检查。

图像生成提示词必须写明小红书3:4比例、连续的纵向主体构图、主体安全区、画面内部字幕安全区、关键对象不可裁切、顶部/底部避让区，以及“禁止横向条幅、上下大块空白、底部通栏；图像不得生成文字、伪文字或字幕”。源图必须原生按3:4生成；不能用直接缩放或中心裁切代替重新构图；预检实际比例失败时，不得以提示词重试次数代替能力证据。

## 排版和导出

当前社媒版遵守“技术分层/视觉融合”：图像只负责无字场景，正文由排版层加入；字幕在 PNG/JPEG 导出时栅格化，但必须落在画面内部自然留白。新流程固定使用 `scene-integrated`，文字只带局部浅色描边/光晕以增强对比，不画整块面板；`soft-card` 和 `narrative-band` 只保留给历史项目。

使用 `scripts/render_social_book.py` 整册输出 PNG/JPEG 和 `social-output.json`。导出前检查 profile、画布尺寸、源图比例、字幕安全区和输出文件是否匹配；不能用一个 profile 的结果改名或简单缩放成另一个 profile。脚本不会创建 PDF 或打印拼版，也不会生成备选版本；脚本通过只证明尺寸、比例、字幕几何和文件条件，不证明人物身份、场景可读性、视觉焦点或审美完成。

### 自动图文排版 V1.0

排版器使用当前字体的实际字形宽度计算换行和高度，不按汉字数量估算。中文逗号、句号、问号、感叹号、分号、顿号和闭引号不能出现在标点行首，也不能单独占一行；原文标点、段落和正文必须逐字保留。行距、正文高度和文字框尺寸由实际测量结果决定，字号只允许在有限范围内调整；无法放入安全区时必须阻断并报告原因。

每页可在 `social_layout.text_safe_area` 之外提供少量 `text_safe_area_candidates`。渲染器按候选顺序检查其与 `subject_safe_area` 的几何关系，并选择不重叠的位置；这不是人脸识别或科学对象识别，不能把几何选择写成自动视觉审核。`scene-integrated` 继续只使用局部浅色描边/光晕，历史文字卡也只能包住实际文字和内边距。

3—4岁页面可记录正文较长、行数较多或对话较长等文字密度提醒；该检查只报告，不自动精简故事。技术输出、密度检查和自动几何检查都不能替代第6、8页及整本的人工 `layout_review`。

## 逐页审核

导出后实际查看每一页，并在 `layout_review` 或社媒审核记录中保存证据。写入 `review.json` 时，`social_pages` 每条记录必须包含独立的 `layout_review`，结构与阅读页审核相同；状态必须为 `passed`，证据必须具体描述文字、主体、遮挡、对比度和节奏，不能只写“已检查”或“通过”：

- 当前小红书画布确为 `1080×1440`、源图为3:4；只有明确要求的历史9:16版本才检查 `1080×1920` 与9:16；
- 主体和字幕没有进入所选 profile 的顶部/底部避让区；
- 人物脸、手、关键道具和知识动作完整，没有被裁掉或字幕遮挡；
- 字幕可读，行数、对比度和行距适合对应平台的阅读距离；
- 角色形象、道具状态、故事动作与相邻页一致；
- 图文属于同一场景，版式没有退化成孤立图片加底部默认字幕块；
- 两个 profile 若都要求交付，分别建立 profile-specific 输出版本并完成各自的逐页审核，不能相互替代或混入同一条单 profile 审核记录。

没有逐页观察和实际证据时，不能把文件存在、脚本通过或打印版已通过说成“社媒审美通过”，也不能声称自动审美通过。`layout_review` 的视觉融合、人物身份、场景可读性和故事连续性仍需人工或模型审核；技术检查不能替代这个边界。
