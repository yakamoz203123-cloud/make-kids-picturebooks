# 故事设计模块

## 第一性原理

儿童继续翻页，是因为想知道“下一步会发生什么”。知识只有在改变角色的行动、判断或选择时，才进入故事；不能把知识段落排列成观察清单。

故事设计只保留一张短卡和一次门禁，不创建新的状态机、数据库或复杂评分系统。故事卡解决“为什么要追读”，分镜再解决“每页怎么画”。

## 最小故事卡

在写 `story.md` 前记录以下字段。每项一句即可；不适用时写清原因，不用补造复杂设定。

```text
story_promise: 孩子想继续翻页等待什么
protagonist_want: 主角现在想得到、找到、保护或完成什么
why_now: 为什么现在必须行动
stakes: 失败会错过、失去或改变什么（低龄作品使用轻量、可逆后果）
obstacle: 什么实际阻碍主角
attempt_feedback_adjustment: 至少两轮“尝试—反馈—调整”
knowledge_tool: 哪条已验证知识改变了下一步行动或判断
choice_turn: 主角在哪个节点改变策略
climax_action: 最大挑战中主角亲自做出的关键动作
emotional_payoff: 结尾给主角和读者的情绪回报
ending_echo: 结尾如何回应开头并产生新意义
```

## 设计顺序

1. 先写 `story_promise`，确认故事不是“读完会知道什么”，而是“读者想看什么发生”。
2. 再写主角愿望、`why_now` 和轻量后果；没有愿望和后果，知识不会自动形成剧情。
3. 设计两轮以上“尝试—反馈—调整”。每轮反馈必须改变下一步条件；失败不是重复观察，而是迫使主角换办法。
4. 把科学事实放进 `knowledge_tool`：它必须帮助主角比较、排除、预测、选择或解释一个结果。
5. 最后设计 `climax_action`、`emotional_payoff` 和 `ending_echo`，再写完整故事。

## 年龄校准

- **3–4 岁**：一个核心问题、两轮可见尝试、一个清楚选择；冲突轻量、结果可逆；重复句式只有在意义发生变化时保留。
- **5–7 岁**：允许误判、关系阻碍或简单倒计时；通常两到三轮尝试；中段必须改变策略。
- **8–10 岁**：可使用多层线索、代价更大的选择和较长悬念，但主线、科学边界和高潮动作仍要清楚。

## 进入分镜前的轻量门禁

以下六项必须能在故事正文或故事卡中找到证据：

1. 前两页内出现可理解的主角愿望。
2. 愿望有“现在就要行动”的理由和可见后果。
3. 至少两次尝试带来新的反馈，主角据此调整。
4. 科学事实改变了行动、判断或选择，而不是只提供解释。
5. 高潮由主角亲自完成，不能由成人或旁白直接公布答案。
6. 结尾回收开头的问题，并提供情绪回报，而不只是复述知识。

出现以下任一情况，故事不得进入正式分镜，先重写故事卡或正文：

- 连续页面只是观察、等待、提问或听讲；
- 错误猜测没有反馈，或反馈没有改变行动；
- 一整段知识可以删掉而不影响角色选择；
- 博物馆、成人或旁白替主角完成发现；
- 结尾只是说“所以我们学到了……”，没有故事回报；
- 为了凑页数拆开一个没有新变化的动作。

## 翻页与节奏

不用强行给每一页塞悬念。只标记高价值翻页点：新问题出现、尝试结果揭晓、线索中断、策略改变、关键发现或结尾回收。相邻页必须有状态变化；没有状态变化就合并、删除或改写。

## 旧稿与续做

已有故事或分镜若未取得故事门禁证据，不得以“续做”身份绕过故事设计；先补做故事门禁。只有故事内容未变且已有有效门禁证据时，续做才可读取最小上下文。

## 与工程流程的边界

- `story-design.md`：故事引擎和门禁证据。
- `story.md`：完整故事正文。
- `storyboard.json`：从故事中选择页面级视觉事件，不重新发明故事。
- `page-manifest.json`：页面生产约束、科学证据和连续性，不负责补救故事缺陷。

故事门禁是人工/模型判断，不是自动审美证明；它只负责阻止明显的知识讲义化和无行动链故事进入分镜。
